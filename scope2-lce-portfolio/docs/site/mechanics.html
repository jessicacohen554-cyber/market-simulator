§The LP, in plain language

Full math: docs/01-lp-formulation.md — this is the summary plus the inventory.

A capacity-choice + hourly-operation problem over a single aggregated node per ISO, the full 8760 hours, solved once per sweep setpoint. It chooses how much of each clean resource and storage tech to build, then dispatches hour by hour against the fixed load and LMP series, buying any shortfall from the grid and selling any surplus at LMP. Because both settle at the hourly price, the optimizer spends its premium budget on the most expensive hours first — that falls out of the LP, it isn't a heuristic layered on top.

Decision variables

build_mw[r] | gen[r,t] | chg[s,t] | dis[s,t] | soc[s,t] | grid_buy[t] | excess[t] | build_energy[k] | exc_ex[t]

exc_ex[t] only exists when additionality_only is on.

Constraints

  • Energy balance (per hour, equality)
  • Generation ceiling: gen[r,t] ≤ cf[r,t]·build_mw[r]
  • Cyclic storage SOC dynamics with duration / split power-energy bounds
  • Fleet-shared hydro monthly energy budget
  • Storage charge provenance (opt-in, ADR 0017): Σchg + excess ≤ Σgen
  • Divert-and-backfill diagnostic (always on) + excess-headroom cut loop (ADR 0018, opt-in)

Two objectives

Mode A — premium_cap (default)

min Σ grid_buy[t]
s.t. net_cost − BAU ≤ δ·Σload[t]

Plus a flat build-size tiebreak (ADR 0019) once matching saturates below a resource's cap.

Mode B — matching_target

min net_cost + ε·Σexcess[t]
s.t. Σgrid_buy[t] ≤ (1−δ)·Σload[t]

Optional strict per-hour 24/7 variant via strict_hourly_matching.

Solver: HiGHS interior-point (crossover off) — fast on the long temporal storage coupling — with a one-time crossover-on retry whenever the fast path doesn't return Optimal.

§The launcher

Implements ADR 0016. Flow: form → queue → CLI → results store → cached report — see the diagram on Overview.

  1. run_lce.sh/run_lce.bat resolve a usable Python and start python -m lce_portfolio.launcher, binding a stdlib ThreadingHTTPServer to 127.0.0.1 on an ephemeral port and opening a self-contained HTML launch page.
  2. Add to queue / Submit queue POST /api/run. One background daemon worker thread drains the queue sequentially — LP solves never overlap.
  3. For each run, build_argv composes an argv (always including --results + --run-id) and the worker calls lce_portfolio.cli.main() in-process — never a forked subprocess.
  4. write_outputs/write_report persist results/<run-id>/ (atomic-ish: writes to <run-id>.tmp/, renames on success) with report.html as a cached file, served back through /reports/<run_id>/report.html.
  5. Every finished run appends one line to launcher/run_log.jsonl (gitignored, machine-local).

Security posture

  • Loopback-only, unauthenticated — binds 127.0.0.1, deliberately no --host flag.
  • Bounded, whitelisted inputs — request bodies capped at 1 MiB; file dropdowns only list four whitelisted directories; run ids validated as a single safe path component.
  • No raw tracebacks reach the browser — every error path renders a short friendly message; the real traceback (if any) only ever prints to the server's terminal.

§Running standalone

scope2-lce-portfolio/ is designed to be copied out of this repo and run on its own. scripts/verify_standalone.sh:

  1. Copies the tool to a fresh temp directory outside the parent repo (a plain recursive copy, so gitignored-but-committed bundled data comes along).
  2. Greps for any real import market_sim statement and fails if found.
  3. Builds a fresh virtualenv from requirements.txt alone.
  4. Runs pytest -q, the synthetic sample sweep, a real-ISO CLI run against bundled data only, and a launcher smoke test.
scope2-lce-portfolio/scripts/verify_standalone.sh
# or, to check a different bundled ISO:
VERIFY_ISO=CAISO scope2-lce-portfolio/scripts/verify_standalone.sh

§Limits & non-goals

  • Single aggregated node per ISO — no intra-ISO transmission/nodal detail.
  • Price-taker — the portfolio never feeds back into the LMP series.
  • No unit commitment — continuous capacity-choice + LP dispatch, not a MIP.
  • Forecast LMP path on hold (ADR 0015) — only the --dummy synthetic mode and the backcast-validation carve-out (bundled 2024 data) work today.
