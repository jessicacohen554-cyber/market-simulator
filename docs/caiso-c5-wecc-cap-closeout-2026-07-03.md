## What caiso-51 does to the cap

In the caiso-51 **backcast keeper** binding path the fitted 7,500 MW scalar is
no longer the operative WECC import limit. Three measured/published mechanisms
supersede it (confirmed in `results/calibration/caiso51_firm_base_solve.log`):

1. **`capacity_deliverability_limits` (Part A)** — the system seam import cap is
   set to the **published branch-group MIC sum**: `16055 / 16452 / 16148 MW` for
   2023 / 2024 / 2025 (solve-log lines 5 / 37 / 66:
   *"seam import cap set to 16055 MW (summed per-area import_limit, delivery year
   2023)"*). This replaces the 7,500 scalar via
   `transmission.apply_deliverability_seam_limit`.
2. **`caiso_corridor_flow_limit`** — measured p95 (month × hour-of-day) ATC
   envelopes on the two corridor links bind *tighter* than either the old 7,500
   or the MIC sum (median import ≈ DSW 5.2 GW / PNW 1.3 GW; solve-log lines
   7 / 39 / 68). This is the effective import constraint.
3. **`caiso_per_hub_intertie`** — the single `WECC_import` node is split into two
   signed, measured-hub corridors (Malin/COI → NP15, Palo Verde/Path-46 → SP15).

The MIC arithmetic sum overstates *simultaneous* capability (parallel WECC paths
sharing source generation — rule #14), so it never binds in the solve; the
measured corridor p95 limits do. This matches the caiso-46 probe finding that
"the true binding representation lies between the tranche build (11.4 GW) and the
MIC arithmetic sum (~16.1 GW)."

**Effect on the audit symptom:** the caiso-46 "fitted-cap artifact" 2023 `>$200`
tail (**161 h** raw / 107 h coverage-masked in the caiso-42 keeper era vs ~21 h
actual) collapses to **0 h** — confirming the audit's claim that the calibrated
cap, not physics, generated the 2023 scarcity tail. The 0 h is an *honest*
collapse (CAISO now has no fitted scarcity mechanism); the missing legitimate
scarcity signal is a standing caiso-51 residual, not something to re-close with a
cap (rule #1).

  propagate into the serialized `scenario_config`). Ground truth is the solve log;
  the recorded config understates the keeper's active levers — an attestation risk.

  is "never enabled in a keeper" (caiso-51 enables Part A) and
  `transmission.split_caiso_import_node_per_hub` said the "8.3 GW" cap is preserved
  (the value is 7,500 MW, superseded by the MIC seam limit in the keeper). Both
  corrected with pointers to caiso-51 in this session.
