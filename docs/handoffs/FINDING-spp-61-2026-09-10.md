## 4. ROOT CAUSE — the SAME defect, one layer down (measured, zero LP)

```
coal_supply_class(6193)          -> ''            (model side: UNRESOLVED)
_coal_supply_class(6193, "")     -> 'COAL'        (bench fallback with no fuel code)
_coal_supply_class(6193, "SUB")  -> 'COAL_PRB'    (bench, WITH the EIA-923 receipt code)
coal_supply_class(6068)          -> 'prb'         (an SPP neighbour, resolved)
```

The SPP benchmark's `classFull` carries `COAL_BIT` / `COAL_LIGNITE` / `COAL_PRB` and **no bare
`COAL`**. So a model class of 4.3551 TWh has no row to be scored against.

**Why 6193 is unresolved:** `scripts/data/derive_coal_supply.py` builds its coal census as

```python
coal_codes = {int(g.plant_code)
              for g in load_fleet_from_csv(iso, iso_config)      # <- no year, NO VINTAGE
              if g.fuel_type == "coal" and int(g.plant_code) > 0}
```

— from the **canonical snapshot, in which Harrington reads `NG`**. It is therefore absent from
`data/raw/_processed-legacy/coal_supply_SPP.csv` (29 rows, no 6193), so `coal_supply_class` falls
through its curated → receipt-derived → retiree-fallback → partial-exit ladder and returns `''`.

**This is the fuel-vintage defect propagating one layer down**: the mis-vintaged registry says
Harrington is gas → it is excluded from the coal census → when the vintage repair correctly makes it
coal, it has no supply class → bare `COAL`. Repairing the registry without repairing the census
built *from* that registry produces exactly what the screen measured. **The prerequisite is not
optional and it was not visible until the arm ran.**
