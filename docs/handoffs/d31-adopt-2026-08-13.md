## 4. Cache-practice finding (duty 2b) — REPORTED, not invented

**The key does not move, and this is the documented house case for that.** Measured:
`ScenarioConfig().cache_key()` = `603c2498bf71d21d` after the change — identical to
`PINNED_DEFAULT_CACHE_KEY`; the ERCOT forecast config hashes to the same value.
`cache_key()` hashes `asdict(config)`, and `QUEUE_CAP_PER_TECH_GW` is a module constant, not a
`ScenarioConfig` field.

**The house practice** is documented in the `src/market_sim/results/cache.py` module docstring
("Cache-key staleness (cache-epoch policy)"). The epoch is deliberately **not** a code token; it
is materialized on two human-read surfaces:

* **Key advances** — recorded at `PINNED_DEFAULT_CACHE_KEY` in
  `tests/regression/test_persisted_identity.py` with a dated cause block. **Not this case.**
* **Same-key invalidations** — a behavior change that leaves every key unmoved — recorded in the
  **cache-epoch ledger** in `cache.py`'s docstring, each entry naming its date, cause, exactly
  what is invalidated and what is NOT. **This is this case.**

Followed accordingly: a dated entry **"Epoch 2026-08-14 — D-31 ERCOT solar queue-cap adoption"**
was added at the head of that ledger. The closest precedent is **Epoch 2026-08-03b** (FFR-SC
NYISO demand-anchor re-derive): likewise constants-level, likewise one ISO, likewise no key
movement, same *Invalidated / NOT invalidated* structure.

This is **not** a cache-*key* ledger edit: no `_CACHE_KEY_OPTIONAL_FIELDS` entry, no defaults
ledger entry, no matrix row, no `scenarios.py` touch (rule 28 respected).

**Invalidated:** cached **ERCOT forecast-mode** bundles — plain forecast, `hindcast=True`, and
the T1-X crossover / T1-FF full-forward legs — solved before this commit.

**NOT invalidated:** every other ISO, and **every backcast bundle and every keeper in every
ISO**. Verified, not assumed: the backcast calibration lane never reads this constant —
`scripts/run_calibration.py::run_year` builds each year's fleet with `fleet.build_base_fleet`
and never calls `evolve_fleet` or `capacity_evolution.new_entry`.
