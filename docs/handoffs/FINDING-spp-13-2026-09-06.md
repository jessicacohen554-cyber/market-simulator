## 0. Headline — the route verdict first

**SPP's programmatic public-data route is anonymous FTP, and it is blocked only by this session's
network policy.** The *SPP Public Data Access* guide (v3.0, July 2023) names it —
**`ftp://pubftp.spp.org`** — and the *Markets Public Data Guide v35* states the credential: user
`anonymous`, password = an email address. **No Marketplace token, no login, nothing the repo lacks.**
What stops it here is the egress: the session's relay carries HTTPS `CONNECT` tunnels to port 443
only. A tunnel to `pubftp.spp.org:21` opens and then never delivers the FTP banner, and — the
control that makes this a transport diagnosis rather than an SPP one — `ftp.gnu.org:21` and
`ftp.debian.org:21` behave identically.

So the charter's stop rule fired for a reason it did not anticipate: not "credentials the repo does
not hold" but "a port the session cannot reach". Payload items (2a)–(2e) were **stopped**, and the
lane went to (3).
