## 0. Headline — read this first

**SPP is registered as the seventh ISO, and the six keepers are unmoved.** `get_iso_config("SPP")`
validates; every ISO-keyed registry on the atomicity list has an SPP entry or a documented exclusion
(§3, §4); the pin flipped in ONE commit (`_ISO_BUILDERS` + `DEMAND_LOADERS` + `SURFACE_ISOS`); and the
byte-identity proof (§2) shows **zero moved solve-surface rows for ERCOT / CAISO / MISO / PJM / NYISO /
NEISO**, the persisted-identity pins at 23/23, and the MISO keeper's `fleet_only` rebuild
hash-identical between this branch and `origin/main`.

Three things the desk must know that the charter did not anticipate (§5 routes each):

1. **The N↔S TTC is a non-binding placeholder, not a reconciled estimate.** No document in the tree
   carries a rated SPP North↔South capability; both spp.org candidates (ITP Manual v3.3, 2022
   20-Year Assessment) answered HTTP 503 to this lane on 2026-09-06, and **SPP-13 (landed on
   `main` while this lane ran, PR #5314) swept all four candidate documents and found that none
   states an MW — the rated interface data is NDA / CEII, not public** (FINDING-spp-13 §0). Under
   rule 14 a "reconciled estimate" needs
   real data to reconcile; with none, the honest registration is the MISO precedent (a placeholder
   that cannot bind, declared as such). Consequence: the first SPP solve is a two-zone copperplate on
   price and SPP-40's P7 STOP gate cannot be met until SPP-13 lands a number.
2. **The D79 declared-hash ledger has no "new ISO row" limb.** `declared_surface` compares a by-ISO
   entry as ONE string, so appending SPP's row to an existing table is an EDIT (check 6), and
   `solve_surface_register.py --declare` refuses already-declared names. SPP's 17 new rows therefore
   land **undeclared** (they stay out of SPP's key — the mechanism's documented behaviour, and SPP
   serves no bundle yet), and the charter's "`--declare` the names whose SPP projection is new" was not
   executable as written.
3. **SPP-12's `spp.csv` cannot be curated as committed.** Its `basis` column reads `coincident`,
   outside the datatype vocabulary `{net, gross, unspecified}`, so `load_forecast.parse_iso("SPP")`
   raises. The spec registers (edition `2025 ITP`, vintage 2025, `default_basis="unspecified"`) and
   the piecewise-linear interpolation is declared; the one-word data correction is routed.

Rule 28 `[R-MECH-MATRIX]`: **no `ScenarioConfig` field was added and no matrix cell moves** — this PR
owes the matrix nothing (duty (c) is for a new field). The SPP shard (`mechanism-matrix/SPP.js`) had
not landed when this lane closed (SPP-21 was RUNNING, branch unknown), so it is neither cited nor
edited. `scripts/check_mechanism_matrix.py --base origin/main` exits 0 (its warnings are pre-existing
anchor drift and the NEISO stamp, none of them this PR's).
