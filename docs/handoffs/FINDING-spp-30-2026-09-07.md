### The layup ordering trap, and how it was handled

`--merit-order-guard` **rewrites the default-read extract** (2721 → 1632 windows, the 1089
reclassified as economic layup moving to the companion). Every other ISO commits the
**guard-off** standard extract alongside the guard-on companion
(`docs/handoffs/patches/README-neiso64.md`: "a full re-derive with the flag absent reproduces
every committed extract blob exactly"). So the guard-on run was made first, then the standard
extract re-derived guard-off — and verified **byte-identical** (`sha256 735d27fe…`, `sha256sum
-c` OK) to the pre-layup run. The committed pair is the same shape every other ISO carries.

## 6. Steps 4 and 5 — run, and why they commit nothing

- **`scripts/tag_mixed_plants.py`** rewrites the ERCOT CAMPD bin sheet
  `data/raw/reference/custom-bin-assignments.csv` in place and takes **no `--iso`**. That sheet
  is ERCOT-only (305 rows, an `ERCOT_Zone` column, zero SPP/SWPP plants); SPP reaches its plant
  groups through the fleet path (`load_fleet_from_csv`), never the bin sheet. It was run
  against a **scratch copy** so the committed sheet could not be disturbed: output
  `bins already split — reconciling registry only` / `registry already in sync with bins`, and
  the copy came back byte-identical. **No SPP rows exist to append**, and both committed
  reference files verified unchanged (`sha256sum -c` OK on
  `custom-bin-assignments.csv` and `master-plant-registry.csv`).
- **`scripts/data/build_offer_curve_overrides.py`** writes no file at all — it turns operator
  tweak lines into stdout JSON for `--offer-curve-delta-json`. Run as `--iso SPP --list`, which
  is the useful non-mutating read here, and it returns a **load-bearing rule 25
  `[R-ISO-SCOPE]` result**: every ISO-scoped class SPP will carry —
  `CC_CHP`, `CC_REGULAR`, `CT_CHP`, `CT_PEAKER`, `ST_GAS` — is **1.0 on every band**
  (`committed`/`econ_low`/`econ_high`/`peak`), and SPP carries **no `phys_*` rows**. ERCOT's
  same classes are at 0.91–1.48 with `peak` up to 13.15 and a full `phys_*` set. No ERCOT-fitted
  multiplier leaks into SPP; the remaining non-1.0 values (`COAL_*`, the three `*_INTERMEDIATE`
  classes) are the generic all-ISO class defaults, visibly distinct from ERCOT's fitted ones
  (SPP `COAL_PRB.econ_low` 0.77 / `econ_high` 1.19 vs ERCOT's 0.70 / 0.94). This is exactly the
  posture SPP-40's gate requires: `authorized_price_tuning` declares **none**.

## 7. ROUTED TO SPP-DESK — one charter step is not runnable as written

**`scripts/data/derive_cc_committed_pct.py --iso SPP` cannot be run, and must not be.**

The script is hard-wired to ERCOT on three independent axes:
1. it has **no `argparse` at all**, so `--iso SPP` is silently ignored — the flag does not exist;
2. it reads `ScenarioConfig().campd_bins_path`, the ERCOT-only bin sheet, and
   `campd.load_campd_hourly(["TX"], [2023])` — **TX only, 2023 only, both hardcoded**;
3. it writes one global un-suffixed `data/raw/_processed-legacy/cc_committed_pct.csv`
   (36 rows, all ERCOT: Nueces Bay, Victoria, …).

Running it would have re-derived and overwritten **another ISO's file** — the explicit
"FILES YOU MUST NOT TOUCH" prohibition — while producing nothing whatsoever for SPP. Giving it
an SPP branch is a change to a derive script, which this lane's charter routes rather than
makes.

**No work is actually missing.** `derive_thermal_tranches.py`'s own module docstring states it
*"Generalizes `scripts.data.derive_cc_committed_pct` (CC-only, ERCOT-only) to **every thermal
group and every ISO***", and its `committed_pct` column is derived by the identical P5-of-
available-CF-over-online-hours method. **SPP's committed-% deliverable is
`thermal_tranches_SPP.csv`, landed in §5** — 18 `CC_REGULAR` rows plus six further groups the
ERCOT-era script never covered. No ISO but ERCOT has a `cc_committed_pct` artifact.

**Ask of SPP-DESK:** amend plan §5 row SPP-30 and §8's prompt to drop
`derive_cc_committed_pct.py` from the SPP sequence (it is a superseded ERCOT-only legacy step),
so no later lane re-runs it and clobbers ERCOT's file. Nothing blocks SPP-40.
