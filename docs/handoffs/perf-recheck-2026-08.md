### 1.4 Why not "hydrate profiles" or a full checkout on a bigger runner

- `hydrate_data.py` profiles are per-ISO corpus-scale (the `ercot` profile alone
  carries the 3.4 GB SCED corpus the tier never reads); the tier needs a
  fine-grained, file-level list — which non-cone sparse patterns express directly,
  and which `actions/checkout` then fetches bloblessly with no extra tooling.
- A paid larger runner fixes both jobs with zero engineering, but is an owner cost
  decision; the measured fix removes the need.

### 1.5 The golden-tier hardening — measured + prototyped

Stock `curate_emissions.py --years 2023` peak = **10.04 GiB** (§1.2). The peak is
structural: per-state frames + `pd.concat` result coexist, `drop_duplicates` builds
a hashtable over a python-string key column, `sort_values` takes a whole-frame copy,
and `write_clean` materializes a second full Arrow table.

**Prototype** `scripts/data/curate_emissions_lowmem.py` (NOT-FOR-MERGE, this branch):
column-wise assembly (parts shed each column as the output gains it), factorized
stable lexsort + neighbor dedupe (provably selects and orders exactly the rows
`drop_duplicates(keep="first")` + `sort_values` produce), column-wise gather, and the
existing `clean_io.write_clean_iter` streaming writer (documented data-byte-identical
layout, built for this problem class).

**A/B on identical inputs (this host):** stock `curate_year(2023)` peak **10.04 GiB**
(VmHWM; phase-attributed: per-state frames + final concat coexist at 6.14 GiB,
`drop_duplicates` hashtable → 8.00 GiB **while removing zero rows**, `sort_values`
copy → 8.81 GiB, `write_clean`'s full Arrow copy → 10.03 GiB), wall 163–168 s.
Prototype: peak **6.45 GiB (−3.6 GiB)**, wall 158.2 s (no cost). Output identity:
byte-equal file size (174,703,675 B both), `assert_frame_equal(check_exact=True)`
**PASS over all 26,534,489 rows**, dtypes equal; file shas differ only via the
`created_utc` provenance timestamp `write_clean_iter` documents (no repo gate
hashes bundle bytes — H4's pre-check finding).

**Runner outcome:** **GREEN on a real runner** (probe run 2, 31873178938, job `curate_emissions RSS probe`): wall **85.6 s, peak RSS 6.39 GiB, exit 0, swap untouched (64 KiB)** — ~1.4 GiB RAM headroom where stock died four times (golden runs 1–2, probe run 1's stock arm, and the 10.04 GiB local measurement vs the 10.8 GiB ceiling). One PERF-B nit: the runner's pandas 4 deprecation-warns the `copy=False` kwarg — drop it (Copy-on-Write is the default there).

Fallback options if the owner prefers zero code change: (i) pay for a larger runner
for this one weekly job; (ii) the runner image already carries 3 GiB swap — a
`fallocate`-swap step could widen the ceiling by a few GiB more, converting OOM death
into slowdown (not tested; the prototype makes it unnecessary).

### 2.7 New finding — basis-export overhead rides the "markup" phase

`export_cross_year_basis` (`model/lp/model.py:1354`) costs ~17–21 s profiled
(~10–16 s real) per solved year: highspy's `getBasis()` returns the 13.2 M
column statuses as a python list of enum objects, and the int8 conversion is
per-element. Two facts measured here:

- **The obvious fix is a measured negative — do not re-run.** A memoized
  `{enum: int}` dict LUT is *slower* than the current `np.asarray(list, int8)`
  (4,651 ms vs 3,716 ms on the 13.23 M vector; `np.fromiter` slower still) —
  numpy's C-level `int()` conversion already beats python dict lookups, and the
  irreducible cost is pybind materializing the object list inside `getBasis()`
  itself. Re-check only if a future highspy exposes an array accessor (the same
  clause Exp-2 recorded for the apply side).
- **The real PERF-B lever is a conditional skip:** under the determinism env
  (`MARKET_SIM_WARMSTART_XYEAR=0` — every goldens capture, keeper replay and
  repro baseline) the exported basis is discarded unread, so exporting is pure
  waste; and on the last year of any run the export has no consumer either.
  Gating the export on "a consumer exists" is behavior-neutral by construction
  and saves ~10–16 s/yr on exactly the runs that are re-executed most
  (goldens/replay). Flagged for PERF-B, not landed.
