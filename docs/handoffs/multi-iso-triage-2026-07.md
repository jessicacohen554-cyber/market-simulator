## 2. Why is MISO absent from rule 16's multi-year keeper list?

**Rule 16 text:** *"Every multi-year ISO's calibration run covers every year the ISO can score, in a
single `--year` invocation and a single bundle: **CAISO / PJM / NEISO / NYISO** → `--year 2023 2024
2025`."*

**Finding: this is a documentation oversight, not a data or calibration gap. MISO already fully
complies and should be added to the list.**

Evidence:
- `frontend/data/backcast/bench/MISO/` has all three years' bench actuals (`2023.json.gz`,
  `2024.json.gz`, `2025.json.gz`).
- MISO's current dashboard keeper, `2026-07-03-miso-39-reserve-pergen`
  (`frontend/data/backcast/registry/2026-07-03-miso-39-reserve-pergen.json`), already carries
  `"years": [2023, 2024, 2025]` — a single bundle, all three years, exactly what rule 16 demands.
- This wasn't a last-minute fix: MISO's *predecessor* keeper, `2026-07-02-miso-38-zonal-reserves`,
  was **already** `"years": [2023, 2024, 2025]` — and that keeper was current on **2026-07-02**, the
  same day rule 16 was authored (`git log` on `CLAUDE.md`: rule 16 lands in the commit merged
  2026-07-02 14:55, one day before miso-39 replaced miso-38 as keeper).
- So at the moment rule 16 was written, MISO (like ERCOT) already had a compliant multi-year
  bundle — it simply wasn't one of the ISOs the rule was written *to fix*. ERCOT's exclusion from
  the list makes sense (it's the calibrated single-year-methodology reference, called out
  separately throughout CLAUDE.md); MISO's exclusion has no equivalent rationale — it reads as
  the rule's author naming the four ISOs known to have single-year-only bundles at the time and
  simply forgetting to also name the one non-ERCOT ISO that already passed.
- 2023–2025 is demonstrably solvable for MISO today: it's the *currently scored* year span, not a
  future aspiration. Nothing about MISO bench coverage, registry state, or the holdout-quarantine
  marker (`calibration-complete.json` shows `"complete": {}` — no ISO has graduated) suggests MISO
  is behind CAISO/PJM/NEISO/NYISO on this specific dimension.

**Conclusion: rule-16 amendment, not a calibration push.** Add `MISO` to the explicit ISO list in
CLAUDE.md rule 16 (`CAISO / PJM / NEISO / NYISO` → `CAISO / PJM / NEISO / NYISO / MISO`). No solve
work is required — MISO already satisfies the rule in practice.

*(Separately, and not a rule-16 matter: MISO's keeper attestation itself says "Determination
NOT-YET" on gate 4 (the >$200 scarcity tail) and pre-existing C1–C3 misses — that's a live open
calibration issue, tracked in `miso-scarcity-tail-diagnosis.md` §open above, not a multi-year-bundle
problem.)*

registry JSON.

  fails C7/C8 (CT_PEAKER 27–33% of energy at binding floors, brushing rule 20's 10% peaker cap) with
  an open scrub thread (`caiso-52-ct-scrub`).
- Stage H stale: doc-00 §0 status table still shows CAISO as `Calib. ref: none | EIA-930: none |
  Backcast: No` despite dozens of registered runs through caiso-52.

**PJM**
- **No numbered prompt pack.** Unlike CAISO(06)/NYISO(07)/NEISO(08), PJM never got a `0X-pjm-…`
  structured pack despite 18 ad-hoc diagnostic docs — those docs substituted for, but were never
  organized into, the protocol's structured build sequence.
- **No `pjm-data-audit.md`** at all (every other ISO has one) — a Stage C/E evidence gap.
- Stage H logging broken: `docs/calibration-log.md` has no PJM entries past "pjm 3–7"
  (2026-06-10, confirmed by direct grep) even though the current keeper is pjm-76 — roughly 69
  tuning iterations were never logged in the canonical calibration log.
  `docs/calibration-best-so-far-pjm.md` is frozen at pjm-38, never updated to pjm-76.
- Stage F incomplete: reserve co-optimization is explicitly "NOT included (memory-infeasible on
  15 GB box)" per the pjm-76 registry text — a known, undelivered market-design module.
- Stage H status table unchanged (`none`/`No`) despite the active keeper.

  organized pack). Does have `miso-data-audit.md`, unlike PJM.
- Stage H barely exists: `docs/calibration-log.md` mentions "MISO" **exactly once**, incidentally
  (confirmed by direct grep) — the miso-25…-39 tuning sequence has no logged entries. No
  `miso-backcast-<year>.md` or `calibration-best-so-far-miso.md` exists, unlike every other ISO.
- Stage G unmet: keeper miso-39 states "Determination NOT-YET" (gate 4 scarcity tail + pre-existing
  C1–C3 misses).
- `propagation-coverage.md` is stale on MISO: still says "no priced import node configured," but

  refreshed after landing.

**NYISO**
- Best-tracked of the non-ERCOT ISOs alongside NEISO: doc-07 P14 sign-off (2026-06-12) genuinely
  updated doc-00, doc-01, and `nyiso-backcast-2023.md` together.
- **But the current keeper has since regressed past that sign-off.** `2026-07-03-nyiso-41-hub-prices`

  ST_GAS 43–65% forced) — with an explicit "NOT-YET" determination. Neither doc-00 nor doc-07 was
  updated to reflect that the live dashboard keeper no longer meets the bar that earned the

**NEISO**

**Cross-ISO summary**
- doc-00 §0's status table is stale for **CAISO, PJM, and MISO** — all three still show
  `none`/`No` despite active, dashboard-registered keepers. Direct Stage H violation ("Update this
  directory's per-ISO status table").
