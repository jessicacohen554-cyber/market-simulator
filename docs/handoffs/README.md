## How to read this index

- **Point-in-time.** This file was generated by a mechanical sweep on
  **2026-09-05** (DOCS-B, model-audit WS4), superseding the 2026-07-19 snapshot,
  which had drifted to 172 rows against 489 top-level files — nearly two thirds of
  the directory was unreachable through its own index. It is a snapshot, not a
  living register: handoffs added after the freeze date will not appear until it is
  regenerated. Do not hand-edit rows; regenerate instead (command below).
- **Top-level files only.** 3 per-lane subdirectories
  (`d37/`, `patches/`, …) hold a further 4 files and are **not** indexed
  here; reach them through the lane doc that owns them.
- **Status source.** These docs predate the `> Status:` header convention (see
  [`../README.md`](../README.md)), so most carry no in-file banner. Status is
  taken from the **`forecast-development-plan-2026-07.md` §9 migration ledger**
  for the 12 docs it names; every other doc defaults to **RECORD** (a
  dated design/evidence record — the program's evidence base, kept as-is and cited,
  never archived). A `RECORD` label here means "not adjudicated by the §9 ledger,"
  not "verified current" — open the doc for its own self-status where it has one.
- **Date** is parsed from the filename (`…-YYYY-MM-DD` → full date; `…-YYYY-MM` →
  month). Non-`RECORD` statuses are quoted from the §9 ledger disposition.
- **`ACTIVE` / `EXECUTED` / `ARCHIVED` / `SUPERSEDED`** rows are the §9-adjudicated
  docs; the forecast plan is the authority for those and should be consulted before
  acting on the doc.
