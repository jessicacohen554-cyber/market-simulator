# Measured ERCOT offer-curve heat-rate multipliers (60-Day DAM)

**Date:** 2026-06-18
**Supersedes (for the gas energy stack):** the *chosen* per-class HR multipliers
(`cc_committed_hr_mult` 1.23, `ct_committed_hr_mult` 1.28, the `*_econ_hr_mult`
set, and the ERCOT `offer_curve_by_group` heights) with multipliers **measured**
from the QSE-submitted DAM energy offer curves, per asset class, pooled 2023-2025.
**Status:** GATED change (moves volumes/prices). Recalibrate-and-compare, not a
silent swap. Builds on the analysis-only

## 1. What changed

The model prices each thermal band as `MC = VOM + (base_HR x fuel_price) x mult`.
Until now the `mult` per band was *chosen* (OEM-typical part-load / peaking
penalties, then calibrated against the LMP). This change replaces those heights —
**for the gas energy stack only (CC / CT / ST_GAS)** — with the multipliers the
real ERCOT QSE offers imply, fed through a committed override JSON
(`inputs/calibration/offer_curve_dam_hrmults.json`) via
`--offer-curve-override-json` and regenerated by
`scripts/derive_dam_offer_hrmults.py`.

## 2. Method (measured, not fit to the LMP residual)

1. Per resource-hour, per energy-curve point `k`:
   `hr_mult_k = (Curve-Price_k / fuel_price_day) / base_HR(resource)`.
   - `fuel_price_day` = delivery-date Henry Hub daily + ERCOT basis (-0.50
     $/MMBtu) for gas; the lignite / PRB delivered-cost trajectory for coal
     (coal is take-or-pay — its offers are *not* gas-indexed).
   - `base_HR` = the **model-fleet** cap-weighted `Plant_Avg_HR_MMBtu_MWh`
     (`inputs/custom-bin-assignments.csv`), so the heat rate we divide by is the
     same one the model later multiplies each plant's own heat rate by. No VOM is
     subtracted (the task formula is `price / fuel / HR`); the model re-applies
     the small constant VOM ($2-4/MWh) on top, a documented, conservative choice.
   - The **committed** band is anchored on the three-part **Min Gen Cost** (the
     all-in $/MWh floor at LSL), not the incremental energy curve.
2. Bin each energy-curve point by `rel = (curve_mw - LSL)/(HSL - LSL)` into the
   model tranches: `econ_low` (rel <= 0.33), `econ_high` (rel >= 0.67); the
   top-of-curve point feeds the peak/scarcity reach.
3. Aggregate per class, **capacity-weighted across resources** (each resource
   contributes its own median per band, then resources are HSL-weighted), pooled
   2023-2025. Report the weighted median + p25/p75.
4. Separate the competitive body (< $1,000) from near-cap bids; report the
   >= $1,000 / >= $4,500 incidence and the realized SPP when they fire.

Two structural findings:

- **The ≥$1k/≥$4.5k bids fire in *normal* hours** (median realized SPP $24-27).
  They are the structural top-of-curve price-wall peakers/steamers always post,
  not conditional scarcity. The genuine scarcity tail is owned by the
  energy+reserve co-optimization, not the offer curve.
- **Coal's measured floor is 2-3x HR** — ERCOT coal Min Gen Cost is dominated by
  *non-fuel* cost, while the model prices coal cheap by design (must-run =
  take-or-pay **sunk fuel**, ~0.95x) so it stays in merit. Feeding measured coal
  would push coal out of merit and collapse its volume.

## 4. The two decisions

ERCOT RTSPP = energy LMP (offers, can hit the $5,000 cap) + ORDC reserve adder,
the sum capped at $5,000. The model's energy+reserve co-opt already makes the
tail, so the body multipliers (steps 1-3) are identical regardless; only the
Peak band and the coal scope are choices.

- **Peak tranche — mode B (full empirical, incl. near-cap bids), per user.**
  Peak = capacity-weighted p50 of each resource's top-of-curve multiplier
  *including* the >= body-cap points. Because cap-bidding is a minority behaviour,
  the resulting peak is still modest (CC 4.3, CT 5.4, ST 4.1) — far below the
  prior CT price-wall of 13.15. **No double-count:** the co-opt ORDC penalties are
  VOLL-anchored (`0.5·VOLL·(LOLP_full+LOLP_half)`, capped at VOLL since LOLP→1 as
  reserves→0) and the LP energy bid wall is `voll = ordc_voll = 5000`, so the
  endogenous co-opt LMP is structurally clamped at $5,000.
- **Coal — excluded, per user.** The measured override scopes to the gas energy
  stack (CC / CT / ST_GAS). Coal stays on its calibrated lignite-sigmoid /
  PRB-floor curve (take-or-pay sunk fuel; gas-divisor inapplicable; the DAM
  `CLLIG` code can't split lignite vs PRB without the missing resource→plant
  crosswalk). Coal is always *reported* by the derivation, never written to the
  override.

### Verdict

The measured override is **not a clean keeper as a whole**. It splits:

- **CC is a genuine win.** Measured CC committed/econ pull CC_CHP from ~+15-20%
  over to within ±4%, and CC_REGULAR stays within band — the measured offers are
  inside the model's CC distribution (consistent with the grounding doc's "CC
  INSIDE, keep").
- **CT + ST_GAS regress hard, together.** Feeding the measured ST_GAS floor
  (committed 2.6x — ERCOT steamers genuinely bid expensive) prices ST_GAS out of
  merit (-56% to -67%), and the cheaper measured CT picks the slack up (+53% to
  +97%) through the documented **−0.25 CT↔ST cross-coupling**
  (`docs/lmp-decomposition-2026-06.md` Task-2). This is the exact non-defensible-
  in-isolation outcome the grounding doc predicted: *"Raising ST toward its
  observed offers is not independently defensible without re-solving that
  coupling."* The measured numbers are honest; the model's ST_GAS class is a
  deliberate calibration swing lever, not a literal offer reproduction, so the
  measured-offer height and the volume target pull in opposite directions.
- **LMP MAE / tail** are within noise (2023-2024), so the regression is a
  **volume** failure, not a price one.

**Action taken:** the measured artifacts (derivation script, override JSON,
comparison, this doc, and both bundles) are committed, but the override is **not
promoted to the default** — the baseline command and its ST/CT volume calibration
stay the keeper (no silent keeper cut). The natural defensible follow-up is a
**CC-only measured variant** (apply the measured CC bands, which improve volumes,
and leave CT/ST on the calibrated curve to avoid the coupling crater); that is a
separate gated change, not silently folded in here.

## 7. Reproduce

```bash
# 1. (re)build the tidy DAM offers, then derive the measured multipliers
python scripts/parse_ercot_dam_offers.py
python scripts/derive_dam_offer_hrmults.py --peak-mode B --write-json

# 2. baseline + DAM 3-yr bundles (everything else identical)
python scripts/run_calibration_full.py --year 2023 2024 2025 \
    --storage-daily-cycling --battery-adder 10 --storage-as-commitment \
    --offer-curve-delta-json inputs/calibration/offer_curve_deltas_cc_merit_ramp.json \
    --coal-lignite-sigmoid --lignite-floor 0.675 --lignite-ceil 1.00 \
    --prb-floor 0.73 --prb-follower-floor 0.63 \
    --curve-mid 0.35 --btm-backfill-year 2024 --cc-duct-peaking \
    --wefor-residual 0.06 --wefor-relief-groups ST_GAS,ST_CHP --energy-reserve-coopt \
    --out-dir results/calibration/ercot_baseline_3yr
# ... + --offer-curve-override-json inputs/calibration/offer_curve_dam_hrmults.json
#     --out-dir results/calibration/ercot_dam_offers_3yr  for the DAM run

# 3. compare
python scripts/_dam_offer_compare.py ercot_dam_offers_3yr ercot_baseline_3yr
```
