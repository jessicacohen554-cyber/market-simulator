The Engine

Solving & Pricing

Why three LP solves per year: the P0→P1→P2 sequence that incorporates startup costs and sets clearing prices.

①

Why Three Solves?

In real markets, generators bid their full cost: fuel, variable O&M, AND startup costs (amortized over their expected run length). But in an ideal "economic dispatch," generators should run if their energy margin (price minus variable cost) covers their fixed startup cost. This creates a chicken-and-egg problem:

  • How long will the unit run? That depends on prices.
  • What price do we set? That depends on which units are committed.
  • Chicken-and-egg: Startup costs and commitment decisions are interdependent.

The solution is the three-pass sequence. It's pure LP — no integer variables or mixed-integer tricks — but it reconciles startup economics with clearing prices.

②

P0 → P1 → P2: The Sequence

Pass 0
P0: Base Cost
Cost vector: Base marginal cost (fuel + VOM + carbon).
Purpose: Discover run lengths from the economic-dispatch solution.
Pass 1
P1: Startup Markup
Cost vector: Base MC + startup markup.
Purpose: Set clearing prices. Reflects cycling and startup burden.
Basis: Warm-start from P0.
Pass 2
P2: Commitment Screen
Decision: Which CC/CT units stay committed?
Purpose: Optional check: decommit units whose margin doesn't justify startup.

Sequence Flow

Warm-starting is key: P1 only changes the cost vector; the matrix and bounds stay the same. HiGHS uses P0's optimal basis and re-optimizes in just a few simplex iterations. This makes P1 nearly free — seconds instead of minutes.

③

P1: The Startup Markup

After P0 solves, the model measures how long each unit runs per month. A unit that runs 80% of the month is expected to be committed for ~24 days. Its startup cost is amortized over that run length:

run_length = number of hours in month where dispatch > 5% of pmax

markup = startup_cost_per_mw / run_length

For example:
  Startup cost = $50,000
  Pmax = 500 MW
  Run length = 480 hours (16 days)
  Markup = $50,000 / (500 × 480) = $0.21/MWh

P1 cost = base MC + $0.21/MWh

Which Units Get the Markup?

Not all units pay startup. The model exempts:

  • Must-run units: Coal with a must-run floor. Already committed, so no startup decision.
  • Nuclear & baseload: Run continuously, so startup is amortized over 12 months.
  • Renewables & storage: No startup cost.
  • Gas CC/CT & gas steam turbines: Full startup markup based on measured run length.

The result: P1 prices reflect the real burden of cycling and startup. If a unit has to start 40 times a month, that cost is spread across its generation. If it runs continuously, the amortized cost is nearly zero.

⚡ Why P1 prices are credible: Real electricity prices include startup burden because generators can't afford to commit without knowing they'll recover their costs. By amortizing startup over measured run lengths, P1 captures this reality and sets prices that reflect what generators actually need to stay in the money.
④

P2: The Commitment Screen (Optional)

P1 sets prices. But not all committed units are profitable at those prices. P2 (optional, default off for most ISOs) performs an economic check: should this CC/CT unit stay committed?

P2 Decommitment Decision
For each CC/CT unit, sum its hourly margin over the year:

margin = (P1_price[zone, hour] − base_MC[unit]) × dispatch[unit, hour]

Decommit if: sum(margin) < startup_cost_per_mw × (1 + irr_hurdle)

In other words: "If the energy margin doesn't cover startup costs with a hurdle rate for IRR, don't commit." This catches units that P1 marginal cost suggested were in-the-money, but weren't actually profitable when you account for startup explicitly.

What Happens After P2?

If a unit is decommitted in P2:

  • Its availability is set to 0 in those decommitted hours. It can't run.
  • Coal is pinned to P1 dispatch. If coal was already committed, keep it at its P1 output (no part-loading re-optimization).
  • A reliability floor prevents blackouts. If committed capacity would drop below P1's thermal dispatch in any zone-hour, restore units until the floor is met.
  • P2 re-solves the LP with this tightened fleet, obtaining final dispatch and prices.

P2 is pure LP — still no MIP. We're just changing availability bounds and re-solving.

⑤

Price Impact Across the Solves

Here's how prices differ between the three passes. This is a hypothetical evening ramp hour (high demand, solar dropping):

Zone P0 Price ($/MWh) P1 Price ($/MWh) Change Why?
North $38 $42 +$4 CC unit starts several times/month; startup markup pushes price up
South (congested) $41 $48 +$7 High startup burden + transmission congestion; importing zone pays more
East (exporting) $35 $36 +$1 Baseload + renewables; minimal cycling; startup markup is small

P0 → P1 price lift: Typically $2–8/MWh during peak/scarcity hours. The lift is smallest in baseload zones (less cycling) and largest in zones with frequent peaking-unit starts.

P1 → P2 adjustment: If P2 commitment screen is on, decommitting unprofitable units can lift prices further by tightening supply. If it's off (default), P2 prices are identical to P1.

⚡ Why this matters for investment: Capacity decisions in next year are based on the prices set by P1 (the default final prices). If you're a gas-CC owner deciding whether to stay in ERCOT, you look at P1 prices — they include your startup burden. This is how the model captures the real incentives that drive investment.
